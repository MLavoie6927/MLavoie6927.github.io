      05 What is a false positive and what is a false negative?

      Answer

      A false positive occurs when a security control identifies legitimate activity as malicious. For example, an approved administrator script might trigger a suspicious PowerShell alert even though the activity is authorized. False positives consume analyst time and, when excessive, contribute to alert fatigue.

      A false negative occurs when malicious activity is present but the control fails to detect it. For example, an attacker may use an execution method that falls outside the rule's current logic. False negatives are usually the more serious risk because an attacker may continue operating while the organization believes no alert exists.

      The objective is not to eliminate one by blindly accepting more of the other. I would test detection logic against known benign and malicious behavior, measure the results, investigate misses, and tune the rule while preserving meaningful coverage.

      07 What is the difference between SIEM and EDR?

      Answer

      A SIEM provides broad visibility by aggregating and correlating telemetry from endpoints, servers, identity, DNS, cloud services, applications, firewalls, IDS/IPS, and network devices. It helps me understand relationships across the environment.

      EDR provides deeper endpoint visibility into process trees, command lines, files, registry changes, persistence, user activity, and network connections. Depending on the platform and my authorization, it can also support actions such as host isolation. In short, SIEM helps explain the environment; EDR helps interrogate and respond to the endpoint. Strong investigations often use both.

      13 How would you investigate and respond to a DDoS attack?

      Answer

      I would first identify the attack type and bottleneck: SYN, UDP, ICMP, DNS amplification, HTTP or HTTPS request flooding, connection exhaustion, or another Layer 3, 4, or 7 pattern. I would compare normal and current interface utilization, packets and connections per second, session state, TCP flags, source distribution, NetFlow or IPFIX, firewall counters, IDS alerts, packet captures, DNS or HTTP rates, and server health.

      If the circuit is not saturated, authorized controls may include zone or DoS protection, SYN cookies or proxying, rate limits, connection quotas, application controls, and restrictions on unnecessary services. If the upstream circuit is saturated, the firewall cannot recover that consumed bandwidth. I would coordinate approved upstream filtering, scrubbing, FlowSpec, RTBH, CDN, Anycast, or provider mitigation as the architecture permits.

      Firewall controls protect systems behind the circuit. Upstream mitigation protects the circuit itself.

      16 What is subnetting, and why is it necessary?

      Answer

      Subnetting is the process of dividing a larger IP network into smaller logical networks by extending the network prefix. It improves address allocation, limits the size of broadcast domains, and makes routing, troubleshooting, and network ownership easier to manage.

      From a security perspective, subnetting creates logical boundaries between users, servers, management systems, voice devices, guests, and other trust zones. Those boundaries do not enforce security by themselves; routers, ACLs, and firewalls must control the traffic that is permitted to cross them.

      Public-Safe Example

      192.0.2.0/24 contains 256 total addresses. Dividing it into four /26 networks gives each subnet 64 total addresses and 62 usable host addresses.

      HR 192.0.2.0/26 Hosts: 192.0.2.1 - 192.0.2.62 Broadcast: 192.0.2.63
      Finance 192.0.2.64/26 Hosts: 192.0.2.65 - 192.0.2.126 Broadcast: 192.0.2.127
      IT 192.0.2.128/26 Hosts: 192.0.2.129 - 192.0.2.190 Broadcast: 192.0.2.191
      Servers 192.0.2.192/26 Hosts: 192.0.2.193 - 192.0.2.254 Broadcast: 192.0.2.255
      HR → InternetAllow
      HR → FinanceDeny
      User VLANs → ServersRequired ports only
      IT → Network devicesAuthorized management protocols
      Guest → Internal networksDeny
      Subnetting is not only about conserving IP addresses. It creates manageable broadcast domains, simplifies routing and troubleshooting, and establishes logical boundaries where VLANs, ACLs, and firewalls can enforce security policy.
