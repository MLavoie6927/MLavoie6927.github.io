# Executive Overview

## Environment

The lab models a regional education technology support organization serving 35 fictional districts. Each district has two sites, multiple VLANs, Windows and ChromeOS endpoints, a local switching layer, centralized security controls, and cloud dependencies. Linux is used for infrastructure/support workloads and diagnostics.

## Operating Model

The support engineer functions as the technical bridge among:

- school staff and students,
- district technology personnel,
- regional network operations,
- cloud administrators,
- hardware/software vendors,
- circuit providers.

Success is measured by **fault isolation quality**, not simply by the number of commands run. Every incident should result in a defensible statement of scope, failed layer, evidence, remediation or escalation, verification, and documentation.

## Core Competencies Demonstrated

1. Endpoint and user support
2. Windows Server / Active Directory / DNS
3. Entra ID / Intune / Microsoft 365
4. Google Workspace / ChromeOS
5. TCP/IP and routed-network troubleshooting
6. VLAN / MDF / IDF operations
7. Firewall and web filtering
8. WAN/circuit escalation
9. SNMP/syslog monitoring and capacity analysis
10. Scripting and repeatable diagnostics
11. Change control and technical documentation
12. Customer-facing communication
