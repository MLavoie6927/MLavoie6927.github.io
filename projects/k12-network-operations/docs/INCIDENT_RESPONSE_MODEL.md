# Operational Incident Response Model

This project uses a support-oriented incident lifecycle compatible with ordinary infrastructure operations.

1. **Detect / Receive** — alert, ticket, phone call, monitoring event.
2. **Scope** — who, what, where, when, how many.
3. **Stabilize** — protect safety/availability; avoid unnecessary broad changes.
4. **Diagnose** — endpoint → identity → LAN → security → WAN → cloud.
5. **Resolve or Escalate** — with evidence and a specific request.
6. **Verify** — repeat tests from affected and unaffected segments.
7. **Document** — cause, action, validation, customer communication.
8. **Improve** — monitor recurrence, update runbook, propose preventive changes.

Security-relevant events (for example student-to-management access) are preserved and handled as potential security incidents rather than ordinary availability tickets.
