# Service Priority & SLA Model

This is a lab model, not an employer policy.

| Priority | Definition | Initial Response Target | Update Rhythm | Example |
|---|---|---:|---:|---|
| P1 | district-wide or safety-critical outage | 15 min | 30 min | all schools offline |
| P2 | building or major shared service unavailable | 30 min | 60 min | high school WAN outage |
| P3 | group/classroom degradation | 4 business hrs | daily | one IDF intermittent |
| P4 | single-user/request | 1 business day | as needed | one profile issue |

## Priority Inputs

- number of affected users,
- instructional/safety impact,
- workaround availability,
- security implications,
- duration,
- recurrence.

A single-user issue can become P1/P2 if it affects a safety-critical role or exposes a serious security condition.
