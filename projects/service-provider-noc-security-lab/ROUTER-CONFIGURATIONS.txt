Complete IOS XE-style candidate configurations
Author: Marc Lavoie

STATUS AND SAFETY
=================
These are public-safe, vendor-aware lab configurations for an isolated
GNS3/EVE-NG-style environment. Documentation ranges and generic RFC1918
addresses are used. Validate syntax against the exact authorized image and
release before deployment. No configuration in this file was taken from an
employer or production network.

COMMON BASELINE - APPLY TO EVERY IOS XE NODE
=============================================
configure terminal
 no ip http server
 no ip http secure-server
 service timestamps debug datetime msec localtime show-timezone
 service timestamps log datetime msec localtime show-timezone
 service password-encryption
 login block-for 120 attempts 5 within 60
 login on-failure log
 login on-success log
 ip domain name noc-lab.example
 username marc privilege 15 secret <SET-IN-LAB-ONLY>
 aaa new-model
 aaa authentication login default local
 aaa authorization exec default local
 crypto key generate rsa modulus 3072
 ip ssh version 2
 ip ssh time-out 30
 ip ssh authentication-retries 3
 clock timezone UTC 0 0
 ntp server 192.0.2.123 prefer
 logging buffered 65536 informational
 logging host 10.50.10.40 transport udp port 514
 logging trap informational
 archive
  path flash:archive-$h-$t
  write-memory
 exit
 line console 0
  logging synchronous
  exec-timeout 10 0
 exit
 line vty 0 4
  transport input ssh
  exec-timeout 10 0
  login authentication default
 exit
end
write memory

NOTE: Replace the placeholder local secret at the console. Never place a real
password in a public repository. In a production environment use centralized
TACACS+/RADIUS, an approved management VRF, and organization PKI.

OPTIONAL RTBH TRIGGER - AUTHORIZED LAB ONLY
===========================================
Use only for the lab-owned public VIP after documenting the service impact.
The upstream must have a pre-agreed discard community and policy. This sample
uses 64501:666 as a lab convention; it is not a universal provider community.

On EDGE-1:
configure terminal
 ip route 198.51.100.50 255.255.255.255 Null0 tag 666 name IR-01-RTBH
 ip prefix-list RTBH-HOST seq 5 permit 198.51.100.50/32
 route-map RTBH-EXPORT permit 10
  match ip address prefix-list RTBH-HOST
  set community 64501:666 additive
 exit
 router bgp 64500
  address-family ipv4
   redistribute static route-map RTBH-EXPORT
  exit-address-family
 exit
end

On ISP-1, pre-stage and validate the provider-side policy:
configure terminal
 ip community-list standard CUSTOMER-RTBH permit 64501:666
 ip prefix-list CUSTOMER-RTBH-HOSTS seq 5 permit 198.51.100.0/24 ge 32
 route-map CUSTOMER-IN permit 5
  match community CUSTOMER-RTBH
  match ip address prefix-list CUSTOMER-RTBH-HOSTS
  set ip next-hop 192.0.2.254
 exit
 route-map CUSTOMER-IN permit 10
  match ip address prefix-list CUSTOMER-IN
 exit
end

Verify:
show bgp ipv4 unicast 198.51.100.50/32
show ip route 198.51.100.50
show route-map CUSTOMER-IN
show ip bgp community 64501:666

Rollback EDGE-1:
configure terminal
 no ip route 198.51.100.50 255.255.255.255 Null0 tag 666
 router bgp 64500
  address-family ipv4
   no redistribute static route-map RTBH-EXPORT
  exit-address-family
 exit
end
