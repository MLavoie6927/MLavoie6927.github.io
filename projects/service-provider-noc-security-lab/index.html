Design Intent

Built around the decisions a hybrid NOC and security engineer must make.

A customer outage can originate at the transport, routing, firewall, application, or threat layer. This project ties those layers together so the investigation can move from service impact to protocol state, security telemetry, containment, recovery, and prevention.

Credibility boundary: This is an original, vendor-aware simulation for portfolio use. It is not affiliated with any employer, does not represent access to a production carrier network, and does not claim hands-on administration of physical Ciena, Nokia, Calix, Alcatel, or Metaswitch equipment.

Architecture

A redundant provider core with explicit trust and telemetry boundaries.

Ten routing nodes, one NGFW, two customer VPNs, a public service edge, and a centralized SOC/NOC stack use documentation and private lab address space only.

Internet edgeISP-1, EDGE-1, eBGP, default-only import, owned-prefix export, RTBH handoff
Provider corePE1, PE2, P1, P2, P3, OSPF Area 0, BFD, MPLS LDP, MP-BGP VPNv4

Complete Build

Staged implementation with configuration, validation, and rollback at every layer.

The complete command set is supplied as downloadable text, while the sequence below shows how the topology is brought online without hiding dependencies between protocols.

  1. 01
    Secure the control plane

    Hostnames, AAA, SSH-only management, NTP, logging, SNMPv3, management ACLs, and configuration archive.

  2. 02
    Establish the underlay

    Address point-to-point links, advertise loopbacks in OSPF Area 0, enable BFD, and verify equal-cost core paths.

  3. 03
    Enable label transport

    Activate MPLS and LDP only on provider-facing links, pin LDP router IDs to loopbacks, and verify label bindings.

  4. 04
    Build customer VPNs

    Create CUST_A and CUST_B VRFs, assign unique RD/RT values, form MP-BGP VPNv4, and apply strict PE-CE route policy.

  5. 05
    Secure the Internet edge

    Import only an approved default, export only the lab-owned documentation prefix, enforce maximum-prefix, and prepare upstream RTBH.

  6. 06
    Deploy NGFW services

    Create zones, routes, DNAT, application policy, log forwarding, threat profiles, zone protection, DoS policy, and rollback snapshots.

  7. 07
    Connect telemetry

    Forward firewall, routing, flow, DNS, IDS, and endpoint data; normalize fields; install correlation searches and health alarms.

  8. 08
    Prove normal operation

    Validate adjacencies, routes, labels, VRF isolation, public-service policy, telemetry freshness, latency, packet loss, and recovery paths.

Chain of Custody

Evidence remains attributable and reproducible.

  • Use UTC collection timestamps and synchronized NTP sources.
  • Record collector, source, method, original location, and case ID.
  • Calculate SHA-256 before analysis and verify it after transfer.
  • Analyze copies while preserving the original artifact read-only.
  • Document every transfer, access event, and disposition.

Validation Status

What is complete and what still requires an authorized runtime.

  • Complete addressing, routing, VRF, firewall, SIEM, and runbook design.
  • Executable offline Python health-check using synthetic telemetry.
  • Static checks for required devices, policies, files, and scenario fields.
  • Device boot, protocol convergence, PAN-OS commit, and live packet evidence remain runtime validation steps.
  • Production thresholds require observed baselines and formal change control.
